# ADR-0010：可商用户型识别评测集与确定性指标

## 背景

`opencv-axis-aligned-baseline-v1` 已在受控双房间图片上打通墙体、房间建议和人工复核，但
受控 fixture 不能代表扫描图、文字、门窗、斜墙和真实住宅分布。没有固定来源、人工真值和
指标契约时，更换识别算法只会得到不可比较的视觉印象。

## 决策

1. 使用 `datasets/recognition` 下的版本化 manifest 作为评测集清单。每个样本记录原图
   SHA-256、已知户型宽度、数据划分、标注状态和米制墙/房间/门窗真值。
2. 每个样本必须记录来源、作者、许可证、具体权利证据、商业使用确认、再分发权限和人工
   审核信息。未确认商业评测权利时 Pydantic 契约直接拒绝；仓库存储还必须允许再分发。
3. 不可再分发但已获得内部商业评测授权的图片使用 `local-only`，放入已忽略的 `private/`；
   这只控制 Git 分发，不能替代授权。
4. `pending` 样本允许先进入待标注队列，但评测时显式跳过；`complete` 样本必须至少包含一面
   非零长度墙。图片缺失、越界或哈希不一致均记为失败，不静默排除。
5. 评测直接调用现有 `RecognitionBackend`，不增加线上接口。墙体按方向无关的两端点误差匹配，
   房间按栅格化 polygon IoU 匹配，门窗按类型、中心和宽度匹配。
6. 报告提供墙体、房间、门窗的 precision/recall/F1、墙端点误差、房间 IoU 和房间语义准确率；
   人工复核会话按 pipeline version 记录耗时，并汇总中位修正秒数。
7. `reportId` 由完整数据集 manifest 摘要、管线版本和阈值确定。同一输入可重复比较，修改标注
   或人工修正记录会改变身份，执行耗时不进入身份。

## 验收

- 自动测试覆盖商业权利和再分发约束、文档示例、反向墙端点匹配、房间 IoU、门窗匹配、图片
  哈希失败、pending 跳过、识别失败计入零召回和真实 OpenCV 后端调用。
- 受控双房间样本稳定得到墙体/房间召回率 1；同一输入两次 `reportId` 一致。
- 真值包含一樘门、当前基线不输出门窗，因此报告门窗召回率为 0，而不是把未支持能力隐藏掉。
- CLI 可读取示例 manifest 并输出 1 个 pending、0 个 evaluated 的明确报告。

## 已知限制与下一步

- 仓库当前只有契约、示例和受控自动测试，没有把历史公共领域户型图计作现代住宅业务基线。
  下一阶段仍需取得并人工标注 20～50 张用户自有、委托或明确开放许可的真实目标样本。
- 公共数据集名称本身不能证明商业授权。CubiCasa5K、FloorPlanCAD、RPLAN 等在权利证据不足或
  带非商业限制时均不得进入默认产品评测资产。
- 当前房间 IoU 使用固定上限的 OpenCV 栅格化，适合首版米制住宅评测；若后续需要亚厘米 CAD
  基准，再引入经过许可和性能评估的精确多边形库。
