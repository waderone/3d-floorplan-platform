# ADR-0011：真实户型候选收集与人工审核边界

## 背景

ADR-0010 已冻结可商用评测集、人工真值和确定性指标契约，但仓库只有受控 fixture。
直接从网络图片或公开数据集抽样会混入非商业许可证、权利证据不完整、立面/剖面和非目标
住宅分布；把提供方的许可标签自动升级为产品的商业授权确认也不可接受。

## 决策

1. 新增离线 `app.recognition_candidates` 工具，只通过 Wikimedia Commons 官方 MediaWiki API
   查询候选，不抓取网页或搜索结果页面。
2. 自动过滤仅保留提供方标记为 `CC0` 或 `Public domain`、最短边至少 400 像素的 JPG/PNG；
   同时保留 page id、原始标题、作者、来源页面、原图/缩略图 URL、原始尺寸、提供方 SHA-1、
   许可标签和许可证据 URL。
3. 候选契约把 `rightsReviewStatus` 和 `selectionStatus` 固定为 `pending`，把商业使用与再分发
   确认固定为 `false`。自动收集结果不能直接进入 ADR-0010 的完整评测 manifest。
4. 下载使用 1024 像素标准缩略图、带项目联系信息的 User-Agent、1～10 秒可配置节流，以及
   对 429/503 的有限重试。已下载文件会重新解码和计算 SHA-256 后复用；单项失败写回队列并
   让命令以失败状态退出，避免不完整批次被误判为成功。
5. 外部图片、候选队列和联系表全部保存在 Git 已忽略的 `datasets/recognition/private/`。
   联系表只显示内部 candidate id 和提供方许可标签，不展示可能含个人联系方式的外部标题。
6. 只有人工核验来源页、具体权利、图面类型、比例和目标域代表性后，才可另行写入评测 manifest；
   几何真值仍需人工标注和复核，不能由现有识别结果自举。

## 验收

- 自动测试覆盖许可/格式/尺寸过滤、待审核硬边界、分页与数量限制、图片解码、SHA-256、
  可恢复下载、联系表和 429 重试。
- 真实收集完成 20/20 个候选和下载，提供方标签分布为 19 个 Public domain、1 个 CC0，
  总下载体积 5,420,655 字节；所有候选仍保持待审核且商业确认均为 false。
- 联系表人工检查能排除立面、剖面、宣传册拼图，并选出清晰、旋转、历史扫描和工程图等
  不同难度候选；这一步只完成选择队列，不等于完成权利审核。
- 用清晰 CC0 试点 `commons-190205778` 实跑现有基线：得到 40 段墙、1 个房间、0 个洞口。
  叠加图表明主边界与多数长墙对齐，但门洞造成墙体碎片、内部房间拓扑和门扇均未识别。

## 已知限制与下一步

- 当前公共领域候选以历史图纸为主，不能替代用户自有、委托或明确授权的现代中文住宅户型；
  阶段 60 仍需取得并标注 20～50 张目标域样本。
- `Public domain` 是提供方元数据，不是本工具给出的法律意见；人工审核必须记录审核人、日期、
  权利证据和再分发结论。
- 下一次识别升级应先以人工真值量化墙体碎片、门窗漏检和房间拓扑失败，再实现拓扑合并、
  门窗检测和房间语义；当前预测不得回填为真值。
