# ADR-0013：独立户型真值标注台

## 背景

ADR-0012 已把候选筛选、权利审核、识别建议和空真值拆开，但还没有可在原图上完成墙体合并、
房间边界、门窗与房型语义编辑的作业工具。Pascal 产品编辑器面向用户场景 revision 和 Wall/Zone
写入，不适合承载离线数据集的工作包身份、图片完整性、标注交接和权利状态。

## 决策

1. 在 `apps/annotator` 建立独立的 Vite/TypeScript 单页工具，不耦合产品编辑器或在线 API。标注数据
   默认只在浏览器内存和用户主动下载的 JSON 中流转，不上传外部服务。
2. 工作包和原图必须配对载入；工具核验候选 id、64 位工作包/图片 SHA-256、图片像素尺寸、比例和
   图面边界后才允许编辑。界面只显示去标识化候选 id，不显示候选原始标题或联系方式。
3. 机器 `suggestions` 始终是独立、可隐藏的橙色参考层。复制建议是显式、幂等操作，复制后生成
   新的 `truth-*` id；建议不会因为工作包载入而自动成为真值。
4. 真值工具支持墙段、房间多边形、门和窗的绘制、选择、控制点拖动、数值修改、房型语义修改、
   删除、撤销与重做。坐标变换与识别后端保持一致，统一输出米制
   `plan-bottom-left-x-right-z-up-m`。
5. 导出契约分为 `draft` 与 `ready-for-review`。草稿允许空几何和空标注人；待复核至少需要一面墙、
   标注人和日期。两种状态都不等同于权利批准，也不会自动写入 ADR-0010 正式评测清单。
6. Python `AnnotationSubmission` 是服务端校验边界，前端 parser 同步约束几何、唯一 id、长度、状态和
   工作包身份。所有动态检查器文本在进入 HTML 前转义，防止不可信草稿注入标记。

## 验收

- TypeScript 单测覆盖工作包解析、建议/真值隔离、像素/米制往返、复制幂等、交接必填项、身份与
  长度边界；Python 单测覆盖草稿、待复核、全局 id 唯一性和工作包/候选错配。
- 生产构建通过；1280×720 真实浏览器中完成演示工作包载入、图片校验、建议墙/房间复制、真值
  计数更新、房间选择和语义编辑，页面首屏布局与图层区分通过视觉检查。
- 后端 CLI 可对工作包和导出 JSON 做二次身份校验，并输出墙、房间、门窗计数。

## 已知限制与下一步

- 本阶段没有双人复核队列、锁定/退回、自动计时或正式 manifest 晋级器；文件仍由人工交接。
- 标注台定位为桌面/横屏平板内部工具，最小布局宽度为 900 px，不面向手机精细绘图。
- 当前只有一个真实候选试点。下一步必须获取并完成 20～50 张合法现代住宅样本的权利审核与双人
  真值复核，再计算基线精度和人工修正中位时间；不得用内置演示数据声称识别准确率。
