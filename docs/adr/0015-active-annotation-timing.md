# ADR-0015：前台有效标注时间自动计时

## 背景

ADR-0010 已把人工修正中位时间定义为识别技术闸门，ADR-0013/0014 也已打通真值编辑、双人复核和
正式样本晋级，但标注人员仍需手工填写耗时。手工回忆无法稳定区分实际编辑、页面离开和长时间
空闲，会让不同识别版本的人工成本失去可比性。

## 决策

1. 标注台在工作包和原图校验后，只有首次绘制、复制建议、拖动、属性修改、删除、撤销或重做
   真值时才启动计时。切换工具、查看建议和填写备注不计为几何修正时间。
2. 计时使用浏览器单调时钟；页面隐藏或窗口失焦时立即暂停，连续 30 秒没有真值编辑活动时只累计
   到空闲阈值。重新聚焦不会自行启动，必须再次编辑才继续。
3. 草稿的可选 `correctionSession` 只保存工作包 `pipelineVersion` 和累计 `durationSeconds`，不记录
   鼠标轨迹、按键内容、焦点历史或墙钟时间段。重新载入草稿从累计值继续，离线时间不会增长。
4. 新标注台导出 `ready-for-review` 时要求累计时间大于零。为兼容此前已交接的文件，Python parser
   和第二人复核仍允许缺少该字段的旧提交；但晋级器明确拒绝无计时提交。
5. 晋级时把提交计时映射为 ADR-0010 `correctionSessions[]`，`reviewer` 与 `completedAt` 分别取首轮
   标注签名的 `annotatedBy` 和 `annotatedAt`。计时算法版本必须与原工作包建议版本完全一致。
6. 有效时间上限沿用评测契约的 7200 秒。超过上限的提交被拒绝，避免异常长期开页污染中位数。

## 验收

- 纯 TypeScript 单测覆盖前台累计、失焦暂停、30 秒空闲截断、草稿恢复、待复核必需时间和算法
  版本错配；生产类型检查与构建通过。
- Python 单测覆盖提交计时范围、工作包版本绑定、旧提交复核兼容、无计时晋级阻断，以及晋级后
  人员、日期、版本和秒数映射。
- 标注台 HANDOFF 区持续显示累计时间和等待、计时中、失焦暂停或空闲暂停状态。

## 已知限制与下一步

- 当前“有效”是前台活动窗口的工程近似，不是逐动作工时审计；最后一次编辑后最多计入 30 秒。
- 离线工具没有可信身份和防篡改时钟，人员仍可修改 JSON。现阶段依靠 SHA-256 双人复核和团队流程，
  生产化后应由服务端任务会话记录累计值与审计事件。
- 自动计时只解决指标采集链路；仍需制作 20～50 张合法真实样本，才能报告有代表性的人工修正
  中位时间和失败类型。
