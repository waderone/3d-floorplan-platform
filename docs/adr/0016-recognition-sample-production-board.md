# ADR-0016：真实评测样本生产看板

## 背景

ADR-0011～0015 已分别建立候选收集、人工筛选、工作包、真值标注、双人复核、自动计时和正式晋级
契约。单张试点可以用多条 CLI 完成，但扩展到 20～50 张时，仅凭目录和文件名无法回答“哪张图卡在
哪一步”，也容易把旧 review、损坏图片或无计时标注误认为已完成。

## 决策

1. 新增 `recognition_sample_production` 离线工具，生产目录按候选 id 隔离，固定使用
   `workpack.json`、`annotation.json`、`review.json` 和 `sample.json` 四个阶段文件；叠加图仍为
   `overlay.png`。
2. `status` 从候选队列和最新人工候选审核出发，重新验证图片 SHA-256/字节/解码、工作包候选与
   curation、标注身份与计时、第二人 review 原始摘要、最新权利状态和正式样本 provenance，生成
   确定性 `reportId` 与逐阶段计数。
3. 候选阶段限定为待筛选、筛选/权利拒绝、待工作包、待/进行中标注、待第二复核、退回修改、待
   权利签署、待晋级、已晋级和 invalid。下游孤儿文件、身份错配、摘要变化、无计时提交或未批准
   权利下出现 sample 都进入 invalid，不按“文件存在”推断成功。
4. `prepare` 只为已人工选中且权利未拒绝的候选生成缺失工作包。已有工作包在图片与 curation
   仍匹配时只读复用；不自动批准权利、不生成真值、不代签标注员或第二复核员。
5. 生产报告仅包含候选 id、图片/作业文件 SHA-256、状态、下一动作、阻断码和文件存在位；作业内容
   改变时 `reportId` 随之改变，但不复制原始标题、作者、联系方式或外部页面文本。真实报告和四类
   作业实例继续保存在 Git 忽略的 `private/`。

## 验收

- 单测覆盖未筛选、筛选拒绝、图片损坏、工作包创建/幂等复用、草稿、待复核、无计时、工作包错配、
  退回、权利 pending、待晋级和已晋级状态。
- 使用现有私有 20 张候选实跑，报告稳定得到 19 张 `curation-required`、1 张
  `annotation-required`；`commons-190205778` 的既有工作包身份保持不变，未被重建或覆盖。
- 完整 FastAPI 回归、Python compileall、CLI help、确定性报告和私有目录忽略边界通过。

## 已知限制与下一步

- 看板是离线文件审计，不提供在线任务认领、账号权限、并发锁或通知；这些能力属于生产数据库与
  队列阶段。
- 当前只有 1 张候选通过人工目标域筛选，且权利仍待真实人员签署。下一步是由负责人筛选更多现代
  住宅来源，并让两名不同人员完成首轮标注与第二复核；工具不会替代这些判断。
- 首批 promoted 样本出现后，才进入 ADR-0010 的批量基线评测和人工修正中位时间统计。
