# ADR-0017：客户实时 3D 样板间

## 背景

项目已经分别验证户型编辑、GLB 发布、三套风格、房间布局、真实资产、Blender 高清出图和户型图
识别，但这些底层模块不能等同于最终产品。最终交付物是客户打开一个链接即可在手机、平板或电脑
实时浏览完整 3D 户型，并在同一户型上切换装修风格。

## 决策

1. 继续使用独立 Babylon.js Viewer 作为客户界面，不加载 Pascal 编辑器，也不新增第二套 WebGL
   技术栈。链接以 `project` 标识已发布户型，以 `style` 标识当前可分享方案。
2. 首次加载并校验 artifact、style、layout 和资产目录；页面内换风格只读取目标 style/layout，
   保留同一个建筑 GLB，并用 `history.replaceState` 更新分享 URL。
3. 风格替换同时覆盖建筑、地面、真实家具角色材质、程序化陈设、环境色和灯光。真实 GLB 加载失败
   时继续使用目录声明的回退并向客户显示数量，不把空房或方块回退伪装成完整结果。
4. 从 layout 的已布置房间动态生成客厅、餐厅和卧室入口；全屋、鸟瞰和房间焦点共享 ArcRotate
   相机，房间半径按窄屏宽高比后退，避免手机裁掉主体。
5. 实时质量使用 ACES、FXAA、轻量 bloom 和模糊指数软阴影。桌面采用 4× MSAA/2048 阴影，
   手机采用 1× MSAA/1024 阴影并限制像素倍率，在画质和触控流畅度之间做显式分档。
6. 客户界面突出全屋方案、装修风格和空间入口，工程 revision/网格统计不作为主信息；加载、错误、
   大模型降级和资产回退仍保持明确状态。

## 验收

- Node 纯逻辑测试覆盖风格目录、动态房间入口、房间焦点和分享 URL；严格 TypeScript 与 Vite
  生产构建通过。
- 使用 ignored `work/layout-e2e-data` 的 `room-e2e-v2` 实跑，首次加载 2 个空间、8 组家具和
  3 个真实模型，0 回退；API 日志确认页面内换风格没有重新下载建筑 GLB。
- 桌面 1280×720、平板 1024×768、手机 390×844 均无横向溢出；现代、北欧、暖木切换和卧室
  焦点完成真实点击与截图检查，最终浏览器 warn/error 为 0。

## 已知限制与下一步

- 当前代表场景和 Kenney CC0 starter 家具仍是低多边形，已证明实时产品闭环，但不代表最终商业
  软装精度。下一步需要扩充高质量家具、灯具、门窗、吊顶和纹理资产，并继续执行移动端体积预算。
- 样板间证明“结构化场景→实时客户方案”成立，不代表任意户型图已经可以无人工校正地稳定生成；
  通用识别成功率仍需合法真实样本、量化评测和失败回退流程支撑。
- 本阶段不包含账号、多租户、公开互联网部署、分享权限或 CDN，这些继续归属产品流程与生产基础
  设施阶段。
