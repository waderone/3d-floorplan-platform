# ADR-0018：商业级实时资产质量切片

- 状态：首个代表性切片验证通过
- 日期：2026-07-21

## 背景

客户实时样板间已经能在同一链接中浏览户型并切换三套风格，但首批 Kenney CC0 家具总计只有
约 55.7 KiB，适合验证加载和回退，不足以代表最终视觉质量。继续只提高采样或统一改色会抹掉
木纹、织物、法线与多材质层次，也无法解决家具轮廓过于低模的问题。

## 决策

1. 资产目录升级为 schema v2，根节点使用多来源 `sources[]`。每个真实模型绑定来源 id，启动时
   同时验证来源引用、本地许可声明、GLB 字节数与 SHA-256；程序化回退继续禁止伪造外部来源。
2. 新资产只采用 Poly Haven 官方资产页和固定的 1K glTF 文件，许可证为 CC0。仓库内导入器固定
   每个 separate glTF 依赖的 URL、字节数和 MD5，导入后再报告 SHA-256，并输出自包含 GLB；产品
   运行时不调用 Poly Haven API，也不随上游目录自动漂移。
3. 目录新增 `replace`、`tint`、`preserve` 三种材质模式。旧 Kenney 模型继续用风格角色替换；
   现代软包椅和床保留内嵌 PBR 纹理并乘算风格色；玻璃/金属吊灯保留作者材质。Viewer 与 Blender
   读取同一字段，不各自维护资产白名单。
4. recipe 可选声明实例 `size`，但必须是正数三维尺寸。当前吊灯从原始约 0.43×0.95×0.43 m
   缩到 0.32×0.70×0.32 m，并抬高到最低点约 2.1 m；两个渲染端继续消费 layout 的最终尺寸。
5. v2 将单资产上限从 2 MiB 显式提高到 3 MiB，同时把代表场景唯一资源预算冻结为 5 MiB。
   重复使用两把同型号椅和两盏同型号灯只计一次下载；超限仍通过 layout manifest 明确暴露。
6. 当前客户 recipe 使用两把现代木框软包椅、现代吊灯和高细节床。维多利亚沙发保留为已审计
   候选但不进入三套现代风格的默认 recipe，避免把“精细”错误等同于“风格合适”。

## 验证结果

- 代表性双房间 layout 输出 11 个 placement、6 个真实模型 placement、0 回退；唯一真实资源
  4,302,348 B，低于 5 MiB 预算。完整三房间 fixture 输出 16 个 placement，唯一资源
  4,318,976 B，同样未超限。
- Viewer 逻辑测试覆盖默认替换、纹理 tint 和非法模式，严格 TypeScript 与 Vite 生产构建通过。
  真实浏览器完成暖木→现代切换、卧室聚焦和控制台检查；390×844、1024×768 均为 ready，
  `scrollWidth == clientWidth`，warn/error 为 0。
- Blender 5.2.0 LTS 使用同一 catalog/layout 跑通 preview：6 个真实 placement、0 回退，约
  2.307 秒输出 1280×720 预览，软包椅、床和吊灯的纹理/尺度均保留。

## 已知限制与下一步

- 这只是证明质量管线成立的代表性切片，不是完整商业资产库。当前床为哥特风格，与现代深色、
  北欧浅色和暖木极简并不完全匹配，必须继续替换为许可清晰的现代床与软装组合。
- 当前建筑 GLB 尚未把权威 Door/Window 开口语义传给 layout，不能凭房间多边形伪造门窗位置；
  下一步应先扩展场景/布局契约，再加入门窗模型、开启区和通道净空约束。
- 实时地面仍以风格色为主，KTX2、LOD、GPU 实例化、CDN 缓存和低端设备降级归阶段 67；5 MiB
  只代表本轮受控场景预算，不等于已经达到最终 5 秒首屏或 30 FPS 指标。
