# ADR-0022：真实样本批次发布与联合评测

## 状态

已接受，2026-07-22。

## 背景

ADR-0016 已能逐候选跟踪权利、标注、复核和晋级状态，ADR-0021 已能消费正式 manifest 衡量
客户主链路可靠性，但两者之间仍依赖人工复制多个 `sample.json`。这会带来漏样本、重复 id、
图片路径错误、修改样本却未提升数据集版本，以及几何报告和主链路报告使用不同输入的风险。

## 决策

1. 新增独立离线批次入口，先重新生成 ProductionReport；只有状态为 `promoted` 的样本可以进入
   正式 manifest。工具不推进人工阶段，不批准权利，也不代签标注或复核身份。
2. 如果某候选已经存在 `sample.json` 但生产审计不再判定为 promoted，整批发布失败，避免损坏或
   过期样本被静默跳过。尚未产生 sample 的待处理候选保留在看板中，不进入统计分母。
3. 每个 promoted sample 再按 dataset root 校验相对图片路径和 SHA-256，并按 sample id 排序后
   构造 EvaluationDataset；重复 sample id 继续由既有契约拒绝。
4. manifest 必须直接写在 dataset root。同一版本、同一规范化内容允许幂等重跑；同一版本内容
   不同则拒绝覆盖，要求显式提升 `datasetVersion`。
5. 批次入口基于同一个落盘 manifest 依次运行识别几何评测和主链路可靠性评测，输出生产、识别、
   主链路和批次摘要四份报告。batchId 绑定 manifest 摘要和三个 reportId，不绑定运行耗时。

## 验收边界

- 自动测试覆盖未晋级拒绝、已晋级组装、manifest 幂等、同版本内容变化拒绝和联合报告落盘。
- 当前私有目录有 20 张候选图、1 个待人工标注工作包、0 个 promoted 样本，因此本决策完成后
  真实成功率仍为“无数据”，不能把测试夹具结果作为对外百分比。
- 下一步仍需由不同人员完成权利审核、首轮标注和第二人复核；每产生一批 promoted 样本即可用
  同一命令刷新真实几何指标、主链路成功率和首个阻断阶段分布。
