# ADR 0029：客户 3D 样板间离线交付

- 状态：已接受
- 日期：2026-07-27

## 背景

实时 Viewer 已经能够消费结构 GLB、三套装修风格、确定性家具布局和可审计 PBR/HDR 资源，
但开发版依赖 `/api`、`/artifacts`、`/catalog-assets` 和 `/render-assets`。只复制 Vite
产物不能脱离开发 API，也无法作为一个可搬运的客户预览文件交付。

本阶段的目标是交付受控商业演示版，而不是把尚未完成的多租户、生产队列、对象存储和正式
真实样本规模化评测包装成生产 SaaS。

## 决策

### 单一 Viewer、两种数据模式

不维护第二套渲染器。开发版继续使用空的 HTML meta 配置和平台 API；打包器只在构建产物
中写入项目标识、`./showroom-data` 数据根目录、`presentation` 展示模式和 `high` 画质档。
Viewer 的解析、布局、材质、相机和风格切换代码保持同源。

### 确定性预览包

`tools/delivery/package_showroom.py` 从一个 ready 项目生成 ZIP，包含：

- Viewer 生产构建；
- 固定 revision 的结构 GLB 和 artifact manifest；
- 三套 style pack 与三份确定性 layout；
- layout 实际引用的模型、许可证和完整资产目录；
- HDR 环境、木地板与地毯 PBR 资源；
- `bundle-manifest.json` 中逐文件字节数与 SHA-256；
- macOS、Windows 和通用 Python 启动器。

ZIP 使用排序文件名、固定时间戳、固定权限与确定压缩参数。同一输入连续打包必须得到完全相同
的 ZIP SHA-256。

### 客户展示模式

演示包默认使用暖木极简和已布置客厅的专用近景。工程统计与说明收起，只保留风格、视角、
动线和全屏控制。客厅近景以沙发、茶几、地毯和灯具为主体，并只在该摄影镜头临时隐藏电视
屏幕；全屋、普通客厅和鸟瞰仍显示完整家具布局。

风格切换后保持客厅摄影镜头，不跳回工程全屋视角。

### 高端设备画质

明确的 `quality=high` 覆盖粗粒度触屏判断，使用最高 2× CSS 像素内部渲染、128 HDR cube、
2048 阴影、4× MSAA、FXAA、ACES 和轻量 bloom。默认开发链接仍可使用自动档，在普通设备上
降级。

### 本地与局域网运行

预览包不能通过 `file://` 双击 `index.html` 运行，因为浏览器会限制 ES module 与资源加载。
随包的 Python 标准库服务器绑定本机端口，并打印电脑与同一 Wi-Fi 手机/平板地址。响应统一
使用 `Cache-Control: no-store`，避免更新同名构建文件后继续使用旧缓存。

## 验收

- 同一输入连续生成两次 ZIP，哈希完全一致；
- 包内每个文件均通过 manifest 字节数和 SHA-256 核验；
- 现代深色、北欧浅色、暖木极简可在离线包内切换；
- 1280×720、1024×768、430×932 实页均无页面溢出；
- 高端手机展示态仍为 `quality=high`；
- 风格切换保持客厅近景，浏览器无 warning/error；
- API、Viewer、Worker、Python 编译和生产构建回归全部通过。

## 明确边界

本决策完成的是可复制、可校验、可向客户演示的商业 MVP。正式公网 SaaS 仍需要合法真实样本
规模化评测、鉴权与多租户、数据库/对象存储、生产队列、监控告警、备份恢复和部署基线。
这些工作不得由离线包的成功替代。
